### **ADR-0142: Harness de Verificación sin UI — CLI First y gRPC Pendiente**

> **Enmienda parcial por [ADR-0165](ADR-0165.md):** ADR-0165 gobierna la arquitectura gRPC y fija Protobuf como fuente del contrato de transporte; ADR-0137 conserva los puertos Rust como contrato de dominio. Este ADR sigue gobernando el canal CLI `verify` y exige un Spike antes de implementar el servidor. Las decisiones anteriores de Flutter/FFI y los detalles de transporte que contradigan ADR-0165 son históricos.

*   **Decisión:**
    El canal CLI `verify` de las features invoca la `public_interface` Rust y emite JSON estructurado. El Core también se expone por gRPC conforme a ADR-0165; su implementación permanece pendiente de un Spike y un slice vertical. Este ADR no decide si el servidor vive en un crate o binario separado ni vuelve a elegir la fuente del contrato: el esquema Protobuf y sus bindings son el contrato de transporte, y los puertos Rust siguen siendo el contrato de dominio.

*   **Contexto y problema:**
    El canal #1 (SVF en el Banco de Verificación, ADR-0117) requiere levantar la aplicación. Para verificar rápidamente el comportamiento del backend —durante desarrollo, depuración o regresión— hace falta un canal directo, sin UI, que invoque inputs/outputs de una feature desde terminal. `drasus verify` cubre esa necesidad. gRPC atiende la frontera de transporte definida por ADR-0165 y no sustituye el canal CLI.

*   **Canal CLI `verify`**

    - **Invocación:** `drasus verify <feature-id> [--input <json>] [--json]`
    - **Implementación:** el subcomando de `crates/app` invoca la `public_interface` Rust; cada feature conserva su contrato tipado.
    - **Salida:** `VerifyOutput` serializado con `serde_json` a `stdout`. Errores a `stderr`; código de salida ≠ 0 en fallo.
    - **Uso en terminal:** `cargo run -p app -- verify third-party-api-gateway --input '<json>'`.
    - El CLI permite comprobar el backend sin iniciar la UI; no sustituye las pruebas unitarias ni de integración.

*   **Implementación gRPC (pendiente, requiere Spike)**

    - El slice vertical implementa una operación unary y un stream requerido por ADR-0166, con autenticación y recuperación según ADR-0165/0166.
    - Cada handler traduce los mensajes Protobuf a la `public_interface` Rust correspondiente; no duplica lógica de dominio ni genera el contrato de transporte desde esos tipos internos.
    - Antes de abrir la Story, el Spike define la integración de generación con el workspace, la ubicación de esquemas y bindings, las convenciones de errores y mapeo, y cómo probar llamadas autenticadas en loopback efímero y en el modo remoto aplicable.
    - ADR-0165 fija la fuente del contrato y ADR-0166 sus requisitos de streams recuperables. El Spike produce una nueva decisión arquitectónica solo si encuentra una elección que esos ADR no cubran; no reabre la fuente Protobuf.

*   **Relación con otros ADRs**

    - **ADR-0165 (UI y gRPC):** fija Protobuf como contrato de transporte y mantiene los puertos Rust como contrato de dominio.
    - **ADR-0166 (streams):** define vista inicial, recuperación, idempotencia y manejo de huecos para la actividad transmitida.
    - **ADR-0117 (Canal #1 — Banco de Verificación):** el Banco de Verificación y el CLI son canales independientes; un fallo en uno no bloquea el otro.
    - **ADR-0133 (pirámide de pruebas):** el CLI no reemplaza las pruebas unitarias ni de integración; es un canal de verificación manual y automatizable, no un sustituto de la pirámide.
    - **ADR-0137 (puertos tipados):** cada handler llama la interfaz pública del dueño del dominio. El esquema de transporte se mapea a esos puertos, pero no se deriva mecánicamente de ellos.

*   **Reglas**

    - **Una sola fuente de lógica (FIJO):** CLI y servidor gRPC llaman a la `public_interface` del feature-crate. Prohibido reimplementar lógica en los handlers CLI o gRPC.
    - **JSON estructurado en el CLI (FIJO):** el subcomando `verify` siempre emite JSON válido a `stdout`. Prohibido output no estructurado (texto plano mezclado con logs).
    - **Implementación gRPC requiere Spike antes de Story (FIJO):** el Spike resuelve integración y convenciones abiertas sin cambiar la fuente Protobuf establecida por ADR-0165.
    - **Independencia de canales (FIJO):** el Banco de Verificación y el CLI no se bloquean mutuamente. Un fallo en uno no impide operar el otro.

*   **Trazabilidad:** ADR-0165 (arquitectura y contrato de transporte gRPC), ADR-0166 (streams recuperables), ADR-0117 (Banco de Verificación), ADR-0133 (pirámide de pruebas), ADR-0137 (puertos tipados y contrato de dominio).
