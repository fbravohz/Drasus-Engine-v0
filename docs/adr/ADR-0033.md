### **ADR-0033: Arquitectura de Despliegue Trimodal**

*   **Decisión:** Soportar de forma oficial tres modos de despliegue del Core Rust. En todos, la interfaz Tauri/React se conecta por gRPC autenticado y sigue un modelo dirigido por estado.
*   **Modos Soportados:**
    1.  **LocalPowerUser (Default):** el host Tauri inicia el Core localmente y se comunica por gRPC de loopback con credencial de corta vida. La interfaz usa sus capacidades normales del host, sin que el Core dependa de la GPU.
    2.  **VpsMonolithic:** el Core puede correr en un VPS local al usuario; la interfaz Tauri/React se conecta por gRPC autenticado. El Core no asume sesión gráfica ni GPU.
    3.  **SaaSCloudEngine (Headless):** el Core Rust corre como daemon independiente, con Features y presets de composición. Opera en hardware remoto del usuario; la interfaz local se conecta por gRPC autenticado. El relé autorizado puede retransmitir actividad durable para atravesar NAT, sin abrir un canal de control no autorizado.
*   **Objetivo:** Adaptar el motor algorítmico a las limitaciones del hardware donde se ejecute, separando estrictamente la computación intensiva de la visualización, brindando la máxima comodidad al usuario final (laptop local) mientras exprime el cómputo remoto (VPS).
*   **Implicaciones:** La UI debe ser 100% dirigida por estado y capaz de desconectarse sin que el Core detenga su operación. Al reconectar recupera snapshot y posición de stream; la presencia efímera no se confunde con actividad durable.
