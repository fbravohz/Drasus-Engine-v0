### ADR-0165: Cliente de Escritorio Tauri + React y Frontera gRPC Local

**¿Qué decidimos?**

Drasus Engine reemplaza Flutter, Dart, `flutter_rust_bridge` y el bridge FFI por una aplicación de escritorio Tauri 2 + React/TypeScript. El Core Rust pasa a ser el único dueño del dominio, la persistencia y la ejecución. Las features conservan sus puertos Rust tipados como contrato de dominio (ADR-0137); Protobuf define el contrato de transporte gRPC autenticado. Un adaptador mapea entre ambas capas. Tauri administra el ciclo de vida y permisos del escritorio, y React consume bindings generados desde Protobuf o una fachada estrecha del host sin duplicar DTOs ni lógica de trading.

La interfaz React usa Tailwind CSS como capa de estilos. `docs/DESIGN.yaml` conserva la fuente canónica de tokens y componentes; el tema de Tailwind proyecta esos tokens a utilidades CSS. El tema predeterminado de Tailwind no define por sí solo la identidad visual de Drasus.

Para escritorio local, el Core escucha solo en loopback con puerto efímero y una credencial de sesión de vida corta creada por el host. La UI no abre listeners ni acepta conexiones entrantes. Para ejecución remota, el mismo contrato gRPC se autentica y autoriza según el plano de ejecución; nunca se traslada la lógica de dominio al cliente.

La frontera gRPC admite llamadas puntuales para comandos y consultas, además de streams de servidor para estado, presencia, progreso, auditoría y cambios confirmados. El stream es suficiente para la actualización en tiempo real del escritorio; Tauri lo entrega a React por el canal interno del host. No se crea un WebSocket paralelo para la aplicación de escritorio. ADR-0166 fija que cada stream parte de una vista inicial y una posición recuperable del registro durable; el stream no es la fuente de verdad ni una notificación efímera.

**¿Por qué lo decidimos?**

La superficie Flutter fue retirada para reconstruir la interfaz sin heredar su biblioteca, sus bindings ni sus decisiones de render. Tauri/React permite una nueva base de escritorio separada del Core y gRPC unifica cliente local, headless y futuros clientes delgados bajo contratos explícitos y verificables.

Tailwind aporta utilidades derivadas de variables de tema, que pueden representar tokens del producto sin convertir cada componente en una fuente paralela de valores ([documentación oficial de variables de tema](https://tailwindcss.com/docs/theme)). El costo aceptado es mantener el mapeo entre `docs/DESIGN.yaml` y el tema de Tailwind; la identidad y las decisiones visuales siguen bajo control del sistema de diseño.

Los puertos Rust expresan operaciones y tipos del dominio; usarlos como esquema de transporte acoplaría el contrato de transporte a la estructura interna y al lenguaje del servidor. Protobuf permite declarar servicios y mensajes independientes del lenguaje y generar bindings para cada cliente. Esa separación añade mapeo explícito entre mensajes y puertos, pero evita que cambios internos redefinan accidentalmente la interfaz externa. Protobuf requiere conservar la identidad de campos y evolucionar los mensajes de forma compatible ([overview](https://protobuf.dev/overview/), [guía de evolución](https://protobuf.dev/best-practices/dos-donts/)); el adaptador y esa disciplina son parte del costo aceptado. La herramienta concreta de generación y su integración con el workspace quedan para el Spike de ADR-0142.

**¿Qué permanece fijo?**

- Rust conserva toda regla de trading, cálculo analítico, autorización de dominio, persistencia y ejecución.
- Local-First, Zero-Docker, checkpoints recuperables y soberanía de datos no cambian.
- Los datos de gran volumen se reducen, agregan y regulan en Rust antes de serializarse; el cliente solo presenta resultados.
- El contrato de dominio vive en los puertos Rust de cada feature conforme a ADR-0137; el contrato de transporte gRPC vive en Protobuf. Los adaptadores realizan el mapeo explícito. Los tipos TypeScript se generan o adaptan desde esa frontera; no se mantienen DTOs paralelos a mano.
- Tailwind CSS es la capa de estilos de React. Los tokens semánticos y componentes se definen en `docs/DESIGN.yaml` y se proyectan al tema de Tailwind; los valores predeterminados del framework no sustituyen la identidad ni el sistema visual de Drasus.
- La actividad compartida del sistema —incluida la presencia y el progreso de agentes— viaja por el contrato gRPC. La interfaz no infiere actividad por polling ni por eventos sintéticos de componentes.
- La actividad durable se transmite solo después de que la transacción de dominio, auditoría y operación se confirma. La presencia de conexión es efímera, tiene vencimiento renovable y nunca sustituye el historial.
- Los contratos Protobuf evolucionan de forma aditiva. Un cliente que no entienda un estado nuevo lo presenta como actividad genérica y conserva la posición de recuperación; no reinterpreta ni descarta el estado de dominio.
- Ningún secreto de bróker ni IP live se expone a la UI, logs de escritorio o endpoint local.
- El uso de WebView queda limitado al shell de Tauri. HTML, SVG, Canvas, WebGL o librerías de gráfica son elecciones de implementación por superficie, con presupuesto de rendimiento, accesibilidad y degradación; no son una segunda capa de dominio.
- La interfaz ofrece una escala tipográfica global e independiente del dominio. `Ctrl++` (o `Ctrl+=` cuando el teclado requiera `Shift`) aumenta la escala, `Ctrl+-` la reduce y `Ctrl+0` restaura el valor base, con el mismo comportamiento esperado en un navegador, VS Code o Codex.
- La escala tipográfica se aplica de forma uniforme al Dashboard, Canvas, paneles inspectores, diálogos, menús y mensajes. El contenido debe reacomodarse sin quedar recortado ni perder accesibilidad.
- Estos atajos pertenecen a la cáscara Tauri/React y no viajan al Core por gRPC. No sustituyen el zoom continuo del Canvas: el zoom del lienzo cambia la cámara y los atajos cambian la lectura de texto de toda la interfaz.
- La interfaz ofrece una paleta de comandos con `Ctrl+Shift+P`, apertura rápida con `Ctrl+P`, búsqueda en la vista con `Ctrl+F`, búsqueda global con `Ctrl+Shift+F`, guardado de cambios editables con `Ctrl+S`, deshacer/rehacer con `Ctrl+Z`/`Ctrl+Y`, cierre o cancelación con `Esc`, ayuda con `F1` o `Ctrl+Shift+?` y cambio de vistas recientes con `Ctrl+Tab`.
- Cuando el foco está dentro del Canvas, `0` ajusta el lienzo a la ventana, `Home` centra la vista, `+`/`-` cambian el zoom del lienzo, `Espacio` más arrastre desplaza la cámara, `Ctrl+C`/`Ctrl+V` copian y pegan nodos y `Delete` elimina la selección con confirmación cuando existen conexiones.
- Los atajos no secuestran la edición normal de campos de texto. Ninguna tecla ejecuta por sí sola una orden real. Pausar nuevas ejecuciones, cancelar operaciones o actuar sobre capital se ofrece desde la paleta de comandos, valida permisos, exige confirmación explícita y queda registrado en la auditoría.

**¿Qué cambia en la entrega?**

- Cada feature con superficie conserva su Cáscara Visual y su SVF, ahora verificadas contra el Core por gRPC y la nueva UI Tauri/React.
- El bootstrap de la interfaz verifica una llamada puntual y un stream de estado, incluida la reconexión y la reconstrucción desde el Core.
- El bootstrap verifica también vista inicial, reanudación desde posición, duplicado idempotente, hueco de secuencia, pérdida de presencia y actualización después de revocar una delegación.
- El empaquetado de escritorio pasa a `desktop-packaging-manager`; la feature Flutter FFI se retira.
- `docs/DESIGN.yaml`, las plantillas y las skills de UI/bridge se rigen por este ADR.
- El bootstrap de Tauri/React debe consumir los tokens de `docs/DESIGN.yaml` mediante Tailwind y comprobar que la cáscara visual no mantiene una fuente paralela de valores.
- El bootstrap de Tauri/React/gRPC debe definirse y validarse como slice vertical antes de migrar superficies de producto.
- El bootstrap de la interfaz valida el aumento, la reducción y el restablecimiento de la escala tipográfica mediante `Ctrl++`/`Ctrl+=`, `Ctrl+-` y `Ctrl+0`, además de comprobar que estos atajos no alteren el zoom del Canvas.
- El bootstrap valida la paleta de comandos, búsqueda, navegación, edición reversible, cierre de superficies y las operaciones del Canvas con foco contextual; también comprueba que ninguna acción sensible pueda ejecutarse sin autorización, confirmación y auditoría.

**Trazabilidad y alcance de reemplazo**

Este ADR reemplaza la elección de frontend y frontera de ADR-0013, ADR-0019, ADR-0029, ADR-0097, ADR-0104, ADR-0106, ADR-0116, ADR-0131 y ADR-0138. Enmienda solo sus aspectos de UI/transporte en ADR-0033, ADR-0117, ADR-0123, ADR-0133, ADR-0134, ADR-0135 y ADR-0139; sus invariantes de producto, seguridad, pruebas y entrega progresiva siguen vigentes cuando no contradigan esta decisión. Aclara ADR-0139: Protobuf es la fuente del contrato de transporte, mientras ADR-0137 sigue rigiendo los contratos de dominio en Rust. Reemplaza las decisiones de transporte gRPC de ADR-0142; ese ADR conserva el canal CLI y el Spike previo a implementar el servidor.

El historial de las decisiones anteriores se conserva con un banner de supersesión. La implementación canónica de la nueva superficie empieza en esta decisión, no en el código eliminado. En modo remoto, el plano autorizado retransmite los registros comprometidos del plano de ejecución con el mismo contrato; el cliente no abre conexiones sin control hacia todos los nodos.
